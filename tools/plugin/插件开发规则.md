# 出厂报告插件开发规则（新增产品/型号指南）

本目录（`tools/plugin/`）是插件开发的**开发包**：
`tek_mso/` 为泰克 MSO/DPO HD 示波器的权威参考实现（TekReport 逻辑 1:1 移植，
已通过与引擎输出的逐格一致性差分验证），`harness.py` 为本地调试台架，
`engine/` 为只读取数引擎镜像（与线上 `backend/app/services/reports/extractor.py` 手动同步）。

新增一个产品或型号系列 = 在 Web「出厂报告 → 报告规则」页（admin）新建规则、上传脚本与模板，**后端零改动、不重启**。

## 一、核心概念与职责边界

一次出厂报告生成的完整管线：

```
盖章完成的产品 → 报告规则匹配型号 → 插件 generate(api) 产出 Excel
    → 引擎归档 → PDF 转换（off / libreoffice / 外部 WPS Worker）
    → MES 上传 → 任务终态（report_jobs 表，页面可查/重试）
```

职责划分（一条红线贯穿始终）：

| 角色 | 负责 | 不负责 |
|---|---|---|
| **插件脚本**（你写的） | 取数、型号解析、渲染 Excel、声明产物 | 存储、PDF、MES、任何网络上传 |
| **服务端引擎** | 规则匹配、执行脚本、归档、PDF、MES、终态管理 | 解析型号字符串、做机型相关决策 |
| **admin** | 维护规则：型号清单、脚本、模板、标准器台账 | —— |

报告规则（`report_rules` 表）的五要素：

1. **型号清单**：绑定该规则的确定型号列表，**精确匹配**（非前缀/通配）
2. **插件脚本**：一个 `generate(api)` 入口的 Python 文件（每族一个，同名覆盖）
3. **Excel 模板**：多个 xlsx（按文件名 upsert），存入对象存储，生成时物化到本地缓存
4. **MES 地址**：该族的校准数据上传接口
5. **自动触发**：盖章完成是否自动入队

## 二、脚本契约

服务端执行 `generate(api)`，`api` 由引擎注入，**只开放以下接口**：

| 接口 | 说明 |
|---|---|
| `api.model` / `api.sn` | 型号与序列号原始字符串。**型号派生（通道/带宽/AFG 等）由脚本自行解析**，服务器不解析 |
| `api.query(table, partition, select, filters) -> list[dict]` | 工厂测试库取数：等价 TekReport 的 `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY date DESC)` 取最新 PASS。**连接级强制只读**，脚本不可能写库。`select` 必须包含比对与取值所需的全部列；表不存在返回 `[]`。数据拆分/比较（如按 vin 正负）由脚本对返回结果自行处理 |
| `api.latest(table, column) -> str` | 该 SN 最新一条记录的某列（date / version / tester）。**版本来源由脚本自定**（如 `api.latest("bandwidth", "version")`） |
| `api.template(name) -> Path` | 上传模板的本地缓存路径（已按规则物化；缓存经归档服务 ETag 校验，模板重传自动更新）|
| `api.work_dir -> Path` | 产物输出目录 |
| `api.standards -> list[dict]` | 标准器台账（manufacturer / pc_name / user_id / model / sn / date）|
| `api.log(msg)` | 写入任务日志 |

### generate 返回值

```python
[{
    "type": "data_report",     # data_report | cal_report | certificate
    "filename": "Tektronix_DPO1074_CNUD001375_1375_P_19092026.xlsx",
    "path": "<work_dir>/...",  # 已保存的文件路径
    "pdf": False,              # 是否需要引擎转 PDF
    "mes": False,              # 是否随 MES 上传（需 pdf 完成）
    "mes_field": None,         # mes=true 时该产物 PDF 在 MES multipart 中的字段名
    "failed_items": [...],     # 缺数据/校验失败明细（引擎落入 report_jobs 供页面展示与重试）
}, ...]
```

`type` / `mes_field` 由引擎消费：全部 `mes=true` 产物的 PDF 就绪后，引擎按各自 `mes_field`
把 PDF 一次性 multipart 上传到规则的 MES 地址。**上传成功后引擎立即清除该产物的归档
对象与本地副本（通用规则，与产品族无关）——MES 即其唯一归档**；未声明 MES 的产物保留在
存储里作为 ATEManager 侧归档。转 PDF 前引擎会对产物做打印设置规范化
（多节回退 scale、单页锁 A4 + fitToPage 1×1），插件无需处理。

## 三、开发流程（本地 → 上传）

### 0. 环境准备

| 项 | 说明 |
|---|---|
| Python 依赖 | `pip install -r requirements.txt`（openpyxl / pg8000 / sqlalchemy） |
| 工厂库连接 | 复制 `.env.example` 为 `.env` 填 `FACTORY_DB_*`（仓库内开发可省略，自动回退读 `backend/.env`），需内网/VPN 可达 |
| 取数引擎 | 统一走 `engine/` 镜像（`app/services/reports/extractor.py`）；**backend 侧改动该文件后需手动同步一份过来**，连接层强制只读 |

1. **建目录**：`<family>/` + `<family>.py` + `templates/`

```
plugin/                     ← 本目录（不随服务端部署，仅开发用；整体即可作为开发包发放）
├── harness.py              ← 本地调试台架
├── engine/                 ← 取数引擎镜像（extractor 与 backend 手动同步）
├── tek_mso/                ← 参考实现（目录名 = 规则名）
│   ├── tek_mso.py          ← 插件脚本（必须实现 generate(api)）
│   ├── templates/          ← Excel 模板（全部经 Web 上传，17 个）
│   └── standards.json      ← 标准器台账（本地调试用；线上在 Web 端维护）
├── _out/                   ← 台架产物（自动生成，不入库）
├── .env.example            ← 工厂库连接模板（复制为 .env；含密码不入库）
├── requirements.txt        ← 台架依赖（openpyxl / pg8000 / sqlalchemy）
└── 插件开发规则.md          ← 本文档
```

2. **写脚本**：参照 `tek_mso/tek_mso.py` —— 取数用 `api.query`，模板坐标为 **0 基**行列（与 NPOI `GetRow/GetCell` 同基准），值格式函数照抄或改写

3. **本地验证**（与"本地执行 TekReport"完全等价）：
   ```powershell
   cd tools/plugin
   python harness.py tek_mso DPO1074 CNUD001375
   ```
   台架用真实工厂库数据执行 `generate()` 并保存产物到 `_out/tek_mso/`；打开 xlsx 与 TekReport 产物（或已知良好样张）核对

4. **上传**：Web「出厂报告 → 报告规则」页（admin）→ 新建规则（确定型号清单（逗号分隔）/ MES 地址 / 自动触发）→ 上传 .py 与全部模板 → 保存即生效（缓存自动失效，不重启）
   - 脚本上传时服务端做 UTF-8 解码、语法编译、`generate(api)` 入口三道校验，失败即拒收
   - 脚本与模板均为同名覆盖

## 四、tek_mso 参考实现要点（照抄即可）

- **型号派生在脚本内**：`_derive(model, sn)` 解析出 `chan_count`（末位数字）、`bandwidth`（第 5-6 位×10）、`has_afg`（尾缀 S）、`cer_no`（SN 尾数=证书号）。这是 TekReport 硬编码口径，新产品族写自己的 `_derive`，**不要期待服务器提供**
- **取数口径**：每表 `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY date DESC)` 取最新 PASS；分区键/过滤条件见 `generate()` 中 D 字典
- **值格式**：`<1V` 显 mV 三位小数否则 V；校准幅度 round2/round3；校准带宽按档位 `<0.5V` 判断；时基 ×1e12、底噪 ×1e6、阻抗 ÷1e6/×1e12；数值单元格直接写数字（C# `ToString()` 口径，不带 `.0`）
- **缺数据语义**：`_need` 抛 KeyError → 记 `failed_items` 并跳过该格（不中断整节，判定与 TekReport 一致）；表不存在的测试项（如无 AFG 机型的 afgsin）整节跳过且**不替换 `<model>` 占位符**
- **标准器校验**：从各测试表 `tester` 前缀（工位电脑名）匹配台账，**标准器校准日期早于被测件 → 证书判失败**
- **Decimal 注意**：pg8000 对 numeric 列返回 `Decimal`，比对/计算前先 `float()`

## 五、红线

1. 脚本 = 受信任代码：仅 admin 可上传，服务端做 compile 与入口检查；**不要在脚本里做任何写操作**（取数 API 本身只读）
2. 不要绕过 `api` 直连数据库（连接串不下发）
3. 坐标体系是 0 基：模板里 Excel 的 A1 = (0, 0)

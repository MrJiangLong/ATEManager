# 出厂报告插件开发流程（本地开发 → 上线验证）

> **读者**：拿到 `tools/reports/plugin/` 开发包、要在本地从零写出一个新产品族插件并上线的开发/工艺人员。
> **读完能做到**：建目录 → 写脚本 → 本地调试 → 自查 → 上传 → 测试服验证 → 发布维护，并能独立排障。
> **版本**：v3 · 对应服务端 `APP_VERSION 2.2.0` · 契约以 `backend/app/services/reports/` 实现为准。
>
> 新增一个产品族 = 在 Web「出厂报告 → 报告规则」页新建规则、上传脚本与模板，**后端零改动、不重启**。
> 维护权限为 **manager / admin**（后端 `require_manager`，不是 admin 专属）。

---

## 总览：你会走这八步

```
Step 0 准备环境 ─▶ Step 1 读懂契约 ─▶ Step 2 建目录 ─▶ Step 3 写脚本
      ─▶ Step 4 本地调试 ─▶ Step 5 自查清单 ─▶ Step 6 上传 Web
      ─▶ Step 7 测试服验证 ─▶ Step 8 发布与维护
```

| 步骤 | 你要产出的东西 | 过关标志 |
|---|---|---|
| 0 准备 | 可连工厂库的 Python 环境 | `python -c "import openpyxl"` 通过、`.env` 就位 |
| 1 读契约 | 知道脚本只做「取数 + 渲染 + 声明产物」 | 能说清 `api` 八成员与 `generate` 返回什么 |
| 2 建目录 | `<family>/` + `<family>.py` + `templates/` | 目录名 = 规则名，脚本名 = 目录名 |
| 3 写脚本 | 一个 `generate(api)` | `py_compile` 通过、骨架能产出 xlsx |
| 4 本地调试 | `_out/<family>/` 下产物 | harness 打印「产物清单校验通过」 |
| 5 自查 | 勾完检查表 | 无遗留项 |
| 6 上传 | Web 上的规则 + 脚本 + 模板 | 规则列表显示 `has_script`、模板数正确 |
| 7 测试服验证 | 一条完整任务 | 终态 `success`、产物可下载、MES 回执符合预期 |
| 8 发布维护 | 版本记录 / 镜像同步 | 发放包不含 `_out/`、`.env`、缓存 |

### 开发包里有什么

| 路径 | 作用 | 会不会随服务端部署 |
|---|---|---|
| `harness.py` | 本地调试台架，执行 `generate()` 并校验产物清单 | 否，仅开发用 |
| `engine/` | 只读取数引擎的**裁剪镜像**（`extractor.py` + 最小 config） | 否 |
| `tek_mso/` | 泰克 MSO/DPO HD 的**权威参考实现**（脚本 + 17 个模板 + `standards.json`） | 否 |
| `_out/` | 台架产物（含真实型号/SN），自动生成 | 否，**不入库、不发放** |
| `.env.example` / `requirements.txt` | 工厂库连接模板 / 依赖 | 否 |
| 本文档 | 开发流程 | 否 |

> 线上真实实现在 `backend/app/services/reports/`（`executor / registry / engine / extractor / mes / pdf / store / scheduler`），
> 开发包里只有 `extractor.py` 的镜像。**遇到行为疑问，以服务端实现为准，本文档附录 D 列出关键行为。**

## Step 0 · 准备环境

### 目标
本机可以连真实工厂测试库、能跑 `openpyxl`、能读参考实现。

### 操作

```powershell
cd tools/reports/plugin
python -m pip install -r requirements.txt     # openpyxl / pg8000 / sqlalchemy / Pillow
copy .env.example .env                        # 填 FACTORY_DB_HOST/PORT/USER/PASSWORD
```

| 项 | 说明 | 怎么确认 |
|---|---|---|
| Python | 建议与服务端一致（3.8+），需支持 `pathlib` | `python --version` |
| 工厂库连接 | **独立分发包必须在包内建 `.env`**（`copy .env.example .env` 后填写密码，只读账号 + 内网/VPN）；台架检测不到配置会直接给出指引并退出。仅仓库内开发可省略（回退读 `backend/.env`） | 台架启动不报「未检测到工厂测试库配置」 |
| **库名 = 型号** | `api.query` 会按 `api.model` 作为库名连库 | 用已知型号（如 `DPO1074`）试跑参考实现 |
| 账号 | 上传规则需要 manager/admin 的 Web 账号 | 找管理员开通 |
| 已知良好样张 | 用于逐格核对（当前**开发包内未附**，需向工艺员索取） | 拿到一份 xlsx |

### 检查点
- [ ] `python -c "import openpyxl, sqlalchemy, PIL; print('OK')"` 通过（Pillow 保证模板图片不丢）
- [ ] 台架启动未报「未检测到工厂测试库配置」，且能跑通参考实现（见 Step 4）
- [ ] 已拿到至少一份样张用于比对

### 常见错误
| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即提示「未检测到工厂测试库配置」 | 包内没有 `.env`，或只填了部分字段 | 复制 `.env.example` 为 `.env`，填 `HOST/USER/PASSWORD`；确认内网/VPN |
| 台架取数全空 | 型号拼错（库名 = 型号）、VPN 未连、`.env` 未生效 | 用已知可用型号重试；`.env` 用 `KEY=VALUE`，不要加引号 |

| `ModuleNotFoundError: app` | 没在 `plugin/` 目录下执行，或打包时漏带 `engine/` 与三个空 `__init__.py` | 补齐目录树后重跑 |

## Step 1 · 用 5 分钟读懂契约

### 一句话职责

> **你的脚本只做三件事：取数、渲染 Excel、声明产物清单。**
> 存储、PDF、MES 上传、任务终态都由服务端引擎负责；型号字符串怎么解析也由你负责（服务器不解析）。

### 你会拿到的 `api`（十一个成员，速查）

| 成员 | 用途 | 详细 |
|---|---|---|
| `api.model` / `api.sn` | 型号 / 序列号原始字符串 | 附录 A |
| **`api.sql(query, params)`** | **任意参数化只读查询 → `list[dict]`**（JOIN / 聚合 / CTE 均可） | 附录 A / C |
| **`api.tables()` / `api.describe(table)`** | **自助探查当前型号库的表/视图与列清单** | 附录 A / C |
| `api.query(table, partition, select, filters)` | 「分区取最新 PASS」的便利封装 → `list[dict]` | 附录 A / C |
| `api.latest(table, column)` | 该 SN 最新一条记录的某列 → `str` | 附录 A |
| `api.template(name)` | 模板本地路径 → `Path` | 附录 A |
| `api.work_dir` | 产物输出目录 → `Path` | 附录 A |
| `api.standards` | 标准器台账 → `list[dict]` | 附录 A |
| `api.log(msg)` | 写服务端进程日志（**不落库、页面看不到**） | 附录 A |

> 复杂取数**直接用 `api.sql`**，不必把需求硬塞进 `api.query` 的固定模板；
> 不知道有哪些表时先 `api.tables()` / `api.describe("xxx")`。

### 你要返回的东西（`generate` 的返回值）

必须返回 `list[dict]`，每个 dict 描述一份产物：

```python
[{
    "type": "cal_report",       # 本族自定义；引擎不解释
    "path": "<api.work_dir>/xxx.xlsx",   # 必填：必须落在该目录内且文件真实存在
    "pdf": True,                # 是否需要转 PDF
    "mes": True,                # 是否随 MES 上传（必须与 pdf=True 搭配）
    "mes_field": "calibrationReport",    # MES multipart 字段名，缺省回退为 type
    "failed_items": [],         # 缺数据明细（建议字符串列表）
}]
```

> `filename` 填了也不生效，服务端一律用 `path.name`。完整字段表见**附录 B**。

### 检查点
- [ ] 能回答：脚本为什么不自己上传 MES？→ 引擎负责
- [ ] 能回答：型号通道数从哪来？→ 自己从 `api.model` 解析
- [ ] 能回答：产物路径写在哪？→ `api.work_dir` 内

## Step 3 · 写脚本

### 3.1 最小可运行骨架（可直接复制）

保存为 `my_family/my_family.py`：

```python
"""my_family 出厂报告插件：最小可运行骨架。"""
from pathlib import Path
import openpyxl


def set_cell(sheet, row, col, value):
    """本族统一 0 基坐标（Excel A1 = (0,0)）；openpyxl 是 1 基，故 +1。"""
    if value is None:
        return
    sheet.cell(row=row + 1, column=col + 1, value=value)


def generate(api):
    model, sn = api.model, api.sn

    # ① 型号派生：服务器不解析，自行实现（参考 tek_mso.py 的 _derive）
    api.log(f"start: model={model} sn={sn}")

    # ② 取数：复杂逻辑请改用 api.sql("SELECT ... WHERE sn = :sn", {"sn": api.sn})，见附录 C.1；
    #    下面 api.query 只是「分区取最新 PASS」的便利封装，PASS 条件写在 filters 里（各表列名可能不同）
    rows = api.query(
        "bandwidth",
        ["sn", "chnum"],                 # partition：非空
        ["chnum", "value", "date"],      # select：必须含分区/过滤/取值所需列
        {"result": "PASS"},              # filters：仅支持等值
    )

    # ③ 渲染：模板坐标 0 基，经 set_cell 转换
    wb = openpyxl.load_workbook(api.template("my_template.xlsx"))
    ws = wb.worksheets[0]
    set_cell(ws, 0, 0, model)
    set_cell(ws, 1, 0, sn)
    for i, r in enumerate(rows[:5]):
        set_cell(ws, 2 + i, 0, r.get("chnum"))
        set_cell(ws, 2 + i, 1, float(r["value"]))   # pg8000 的 Decimal 先转 float

    # ④ 落盘：必须在 api.work_dir 内
    path = Path(api.work_dir) / f"{sn}_data.xlsx"
    wb.save(path)

    # ⑤ 声明产物
    return [{
        "type": "data_report",
        "path": str(path),
        "pdf": False,
        "mes": False,
        "mes_field": None,
        "failed_items": [],
    }]
```

### 3.2 按这个顺序填充真实逻辑

| 顺序 | 做什么 | 参考位置 |
|---|---|---|
| 1 | `_derive(model, sn)`：通道/带宽/选件/证书号 | `tek_mso.py` `_derive` |
| 2 | 列出每张测试表的 `table / partition / select / filters`，集中成一个 `D` 字典 | `tek_mso.py` `generate` 的 D 字典 |
| 3 | 值格式函数（mV/V、round2/3、倍率）与 `set_cell` | `tek_mso.py` `_fmt_v` / `_cal_amp` / `set_cell` |
| 4 | 每份报告的渲染函数，返回 `failed_items` | `_render_data` / `_render_cal` / `_render_cert` |
| 5 | 标准器校验（按 `tester` 前缀匹配 `api.standards`，校准日期早于被测件判失败） | `_find_standard` / `_std_date` |
| 6 | `plan` 列表声明每份产物的 `type / 模板 / pdf / mes / mes_field`，循环产出 | `generate` 的 `plan` |

### 3.3 六个必须注意的点

| 点 | 说明 |
|---|---|
| **坐标 0 基** | 模板里 A1 = `(0,0)`；`openpyxl` 是 1 基，必须 `+1`（照抄 `set_cell`） |
| **数值格式** | 数值单元格直接写数字（不带 `.0`）；`<1V` 显 mV 三位小数等口径照参考实现 |
| **Decimal** | pg8000 对 numeric 列返回 `Decimal`，比较/计算前 `float()` |
| **缺数据不中断** | 抛 `KeyError` → 记入 `failed_items` 并跳过该格；表不存在的测试项整节跳过、不替换 `<model>` 占位符 |
| **版本来源** | 由脚本自定；参考实现跨 13 张表取 date 最新（`_latest_version`），不是单表 `api.latest(...)` |
| **模块级代码** | 只放 import / 常量 / 纯函数：上传时与规则加载时都会真实 `exec` 模块级代码（见附录 D） |

### 检查点
- [ ] `python -m py_compile my_family/my_family.py` 通过
- [ ] 脚本里只用附录 A 列出的八个 `api` 成员
- [ ] 所有产物 `path` 都拼在 `api.work_dir` 下
- [ ] `templates/` 里有脚本 `api.template()` 引用的每一个文件名

### 常见错误
| 现象 | 原因 | 处理 |
|---|---|---|
| 上传被拒 `script_entry_missing` | 没定义 `generate`，或名字拼错 | 检查函数名 |
| 上线报 `artifacts[0].path missing or outside work_dir` | `path` 用了相对路径/写到别处 | 一律 `Path(api.work_dir) / filename` |
| 单元格全错位一列 | 忘了 0→1 基转换 | 用 `set_cell` |
| 模板找不到 | 文件名大小写/后缀不一致 | 与 `templates/` 逐字核对 |

## Step 4 · 本地调试（harness）

### 操作

```powershell
cd tools/reports/plugin
python harness.py my_family DPO1074 CNUD001375
```

台架会：加载 `my_family/my_family.py` → 用真实工厂库数据执行 `generate()` → 产物落
`_out/my_family/<HHMMSS>/` → 按线上口径校验产物清单 → 打印每份产物与失败项。

### harness 校验什么 / 不校验什么

| 校验 | 台架 | 线上 |
|---|---|---|
| 返回值是 `list[dict]`、`path` 落在 `work_dir` 内且存在 | ✅ | ✅ |
| `filename` 以 `path.name` 为准、`mes_field` 缺省回退 `type` | ✅ 打印实际值 | ✅ |
| `mes=true && pdf=false`、多个 `mes_field` 重名 | ✅ 主动告警 | 运行时失败/覆盖 |
| 字段规范化、MinIO 归档、PDF 转换、MES 上传、任务终态 | ❌ | ✅ |
| 300s 超时、异常转任务 failed | ❌ | ✅ |

**台架与线上不等价**，差异清单：

| 项 | 台架 | 线上 |
|---|---|---|
| `api.template` | 直接读本地 `templates/` | MinIO ETag 校验后物化缓存 |
| `api.standards` | 读 `standards.json` | 按 rule 查 DB（`cal_date→date`） |
| `api.work_dir` | `_out/<family>/<HHMMSS>` | `REPORT_WORK_DIR/<model>/<sn>` |
| `api.log` | `print` | 服务端进程日志 + 内存列表（不落库） |
| 执行约束 | 无超时/异常包装 | 300s 线程超时、异常转任务 failed |

> `api.sql` 的资源上限**不在差异清单里**：台架与线上读同一组 `REPORT_SQL_*` 环境变量
> （.env.example 有注释模板），在包内 `.env` 填与线上相同的值即完全对齐。
>
> **台架通过是必要不充分条件**：上线前必须在测试服跑完整任务（Step 7）。

### 检查点
- [ ] 打印「产物清单校验通过」，无 `mes`/`mes_field` 告警
- [ ] 打开 `_out/` 里的 xlsx，与已知良好样张逐格核对（数值、格式、占位符）
- [ ] `failed_items` 数量符合预期（缺数据项应被记录而非静默吞掉）

## Step 5 · 上线前自查清单

**返回值 / 路径**
- [ ] `generate` 返回 `list[dict]`，每项是 dict
- [ ] 每个 `path` 落在 `api.work_dir` 内，且 `wb.save()` 真的执行过
- [ ] 不依赖 `filename` 字段传名（服务端用 `path.name`）
- [ ] `failed_items` 用字符串列表，非空项确实代表缺数据

**PDF / MES**
- [ ] `mes=true` 的产物一定 `pdf=true`
- [ ] 每个 `mes=true` 产物有唯一 `mes_field`（不重名，否则 multipart 覆盖）
- [ ] 已与 MES 侧确认字段名与 `success` 响应契约（附录 D）

**取数**
- [ ] 复杂查询走 `api.sql`，**值全部用 `params` 绑定**，且带 `WHERE` / `LIMIT` / 聚合（不会全表扫描）
- [ ] 需要的表/列已用 `api.tables()` / `api.describe()` 核对过
- [ ] 每张表的 `filters` 里显式写了 PASS 条件，且列名与该表一致
- [ ] `filters` 只用了等值条件；`partition` / `select` 非空
- [ ] 每张测试表都有 `date` 列；`select` 含全部比对/取值列
- [ ] `api.latest` 调用有 `try/except`（缺表会抛异常）
- [ ] numeric 值已 `float()` 再比较

**运行约束**
- [ ] 模块级无 I/O、无连库、无线程
- [ ] `generate` 能在 300s 内返回；无死循环、无无超时网络调用
- [ ] 没有 `import` 数据库/网络库，没有绕过 `api` 直连
- [ ] 异常会自然抛出或转成 `failed_items`，没有吞掉所有异常

**模板 / 标准器**
- [ ] 脚本引用的模板文件名与 `templates/` 完全一致（大小写敏感）
- [ ] `api.template()` 返回值直接交给 `openpyxl.load_workbook`
- [ ] 标准器匹配逻辑用的是 `api.standards` 的 `date` 字段

### 症状 → 原因速查

| 线上症状 | 最可能原因 | 修法 |
|---|---|---|
| `generate() must return a list` | 返回了 None / dict | 统一 `return [ ... ]` |
| `artifacts[i].path missing or outside work_dir` | 路径写死或没保存文件 | 用 `api.work_dir` |
| 任务 `failed` 且 `job.error` 是 traceback | 插件抛异常 | 看 traceback；缺表/Decimal/坐标 |
| `plugin generate() timeout after 300s` | 长循环或卡住的网络调用 | 优化取数，避免全表扫描 |
| `mes_status=failed: missing pdf file` | `mes=true` 但 `pdf=false` 或 PDF 未转换 | 补 `pdf=true`；确认 `REPORT_PDF_MODE` |
| 任务 `partial` | PDF mode=off 或有产物带 `failed_items` | 部署 PDF 转换器；核对缺数据 |
| 页面看不到 `api.log` 内容 | 设计如此，日志只在服务端 | 查服务端日志、`job.error`、`job.failed_items` |

## Step 6 · 上传到 Web 生效

### 操作顺序

1. 登录 Web（**manager / admin**）→「出厂报告 → 报告规则」Tab → **新建规则**
2. 填规则字段：

| 字段 | 填写 | 约束 |
|---|---|---|
| 规则名 `rule` | 与目录名一致，如 `my_family` | `^[a-zA-Z0-9_]+$`，1–64 字符 |
| 型号清单 `models` | 逗号分隔的确定型号 | **精确匹配**，非前缀/通配；至少 1 个 |
| `mes_url` / `mes_void_url` | 该族 MES 上传/作废地址 | 留空 = 禁用该功能，无全局回退 |
| `auto_trigger` / `enabled` | 按需 | 盖章完成是否自动入队 |

3. 上传 **全部 `.xlsx` 模板**（按文件名 upsert，同名覆盖）
4. 上传 **`.py` 脚本**（同名覆盖）
5. 保存即生效：上传后服务端显式 `reset_cache()`，**不需要重启后端**

### 上传时服务端会做的三道校验

| 顺序 | 检查 | 失败码 |
|---|---|---|
| 1 | 文件名以 `.py` 结尾 | `script_not_python` |
| 2 | 内容可按 UTF-8 解码 | `script_not_utf8` |
| 3 | `compile()` 成功，且 `exec()` 后命名空间里 `generate` 可调用 | `script_syntax_error` / `script_entry_missing` |

> 注意：第 3 步的 `exec` 会**真实执行模块级代码**；不检查 import、不检查 `generate` 的参数签名、不检查脚本大小。
> 规则首次加载时还会再 `exec` 一次 —— 模块级代码共执行两次。

### 检查点
- [ ] 规则列表里 `has_script=true`、模板数量与本地一致
- [ ] 型号清单与要生成的件完全对应（精确匹配）
- [ ] `mes_url` 已填或明确确认本族不走 MES

## 附录 A · `api` 契约速查

| 成员 | 签名 / 类型 | 精确语义 |
|---|---|---|
| `api.model` | `str` | 型号原始串，**同时是工厂库库名**；派生属性自行解析 |
| `api.sn` | `str` | 序列号原始串 |
| `api.work_dir` | `Path` | 线上 `REPORT_WORK_DIR/<model>/<sn>`；产物必须落在此目录内 |
| `api.standards` | `list[dict]` | 字段 `manufacturer / pc_name / user_id / model / sn / date`（DB `cal_date` → `date`） |
| `api.template(name)` | `str -> Path` | 模板本地缓存路径；ETag 不一致才重下，远端 ETag 取不到时信任本地缓存 |
| **`api.sql(query, params=None)`** | `-> list[dict]` | **任意参数化只读查询**：只查当前型号分库（`api.model`），值一律走 `params` 绑定；非 `SELECT/WITH/...` 语句给友好报错，写操作由只读事务在 PG 层拒绝。事务级超时 `REPORT_SQL_TIMEOUT_MS`（默认 30s）、结果上限 `REPORT_SQL_MAX_ROWS`（默认 5 万行），超限报错。返回 `Decimal` 需自行 `float()`。见附录 C |
| **`api.tables()`** | `-> list[dict]` | 当前型号库 `public` schema 下表与视图清单：`table_name / table_type`（含 VIEW） |
| **`api.describe(table)`** | `-> list[dict]` | 表/视图列清单：`column_name / data_type / is_nullable / ordinal_position`；表名参数绑定，不存在返回 `[]` |
| `api.query(table, partition, select, filters)` | `-> list[dict]` | 「分区取最新 PASS」便利封装，固定 SQL 模板，见附录 C |
| `api.latest(table, column)` | `-> str` | `str(... or "")` 恒返回字符串；**缺表抛异常**，调用方需兜底 |
| `api.log(msg)` | `-> None` | 服务端进程日志 + 内存列表；**不落 `report_jobs`、页面看不到** |

## 附录 B · `generate` 返回值契约（硬校验）

返回值必须是 `list[dict]`，由 `executor._validate_artifacts` 逐项校验，任一不满足 → **整个任务 failed**。

| 字段 | 类型 | 必填 | 缺省 | 引擎处理 |
|---|---|---|---|---|
| `path` | `str`/`Path` | 建议必填 | `work_dir / filename` | 字符串前缀须落在 `work_dir` 内**且文件存在**，否则 `ValueError` |
| `filename` | `str` | 否 | — | **被 `path.name` 覆盖**，填了不生效 |
| `type` | `str` | 否 | `report_<i>` | **无合法值集合**；引擎不解释，只用于日志、失败项前缀、`mes_field` 回退 |
| `pdf` | `bool` | 否 | `False` | `true` → 打印设置规范化 + 转 PDF |
| `mes` | `bool` | 否 | `False` | `true` → PDF 参与一次性 multipart 上传 |
| `mes_field` | `str` | `mes=true` 时建议必填 | 回退为 `type` | 多个产物重名会互相覆盖 |
| `failed_items` | `list` | 否 | `[]` | 元素被 `str()` 化并加 `"<type>: "` 前缀；非空即令该产物 `failed=true` |

引擎另生成 `local_path / object_key / pdf_status / pdf_object_key / failed`，插件不要声明。
失败信息：`generate() must return a list` · `artifacts[i] is not a dict` ·
`artifacts[i].path missing or outside work_dir` · `plugin generate() timeout after 300s` · `plugin raised: <traceback>`。

## 附录 C · 取数：`api.sql`（任意查询）与 `api.query`（便利封装）

### C.1 `api.sql` —— 任意参数化只读查询

JOIN、聚合、窗口函数、CTE、子查询、自定义排序都支持，**SQL 由插件自己写**：

```python
# 值一律走 params 绑定（不要 f-string 拼值）；标识符大小写敏感，必要时写双引号
rows = api.sql(
    """
    SELECT b.chnum, MAX(b.value) AS peak, count(*) AS n
    FROM bandwidth b
    JOIN dc d ON d.sn = b.sn AND d.chnum = b.chnum
    WHERE b.sn = :sn AND b.result = :ok
    GROUP BY b.chnum
    ORDER BY b.chnum
    """,
    {"sn": api.sn, "ok": "PASS"},
)

tables = api.tables()                 # [{"table_name": ..., "table_type": "BASE TABLE"/"VIEW"}, ...]
cols = api.describe("bandwidth")     # [{"column_name", "data_type", "is_nullable", "ordinal_position"}, ...]
```

规则与边界：

| 项 | 说明 |
|---|---|
| 库的范围 | **只查当前型号分库**（库名 = `api.model`），不支持跨库；PG 跨库需 dblink/FDW，不在契约内 |
| 语句类型 | 只放行 `SELECT / WITH / TABLE / VALUES / SHOW / EXPLAIN` 开头的语句（给友好报错）；**这不是安全边界** —— 写操作由连接级 `SET default_transaction_read_only = on` 在 PG 层硬拒绝 |
| 参数 | 值必须走 `params`（`:name` 绑定）；不要拼接 SQL 字符串。标识符自行用双引号，服务端不转义 |
| 资源上限 | 事务级 `statement_timeout`（`REPORT_SQL_TIMEOUT_MS`，默认 30s）+ 结果行数 `REPORT_SQL_MAX_ROWS`（默认 5 万行），**超限报错并令任务 `failed`**（不是截断返回）。工厂库是**生产测试库**，请自觉加 `WHERE / LIMIT / 聚合`。两者是服务端配置、运维可调；开发包台架读**同名环境变量**（在包内 `.env` 填同值即与线上一致，见 Step 0 / Step 8） |
| 返回 | `list[dict]`；numeric 列是 `Decimal`，比较/计算前 `float()`；无行返回 `[]` |
| 方言 | PostgreSQL（`pg8000`）。`information_schema`、`set_config` 等为 PG 专有 |
| 观测 | SQL 摘要（不含参数值）+ 行数 + 耗时写**服务端日志**；不落 `report_jobs`，页面看不到 |

> `api.tables()` / `api.describe()` 是自助探查入口，解决「给了任意 SQL 却不知道有哪些表」；
> 两者走同一只读连接与**事务级超时**，表名参数绑定；`information_schema` 结果集很小，
> 因此**不设行数上限**（与 `api.sql` 的契约有意不对称）。

### C.2 `api.query` —— 固定模板（存量插件用的便利封装）

```sql
WITH ranked AS (
  SELECT <select 列>,
         ROW_NUMBER() OVER (PARTITION BY <partition 列> ORDER BY "date" DESC) AS rn
  FROM "<table>"
  WHERE sn = :sn AND <filters 各列等值条件>
)
SELECT <select 列> FROM ranked WHERE rn = 1
```

七条约束：

1. **「最新 PASS」不是内置过滤**：是否只取 PASS 由 `filters` 里的 `result` / `resresult` 等列决定，**各表列名不同**（参考实现 D 字典）；不传就不过滤。
2. `filters` **仅支持等值**，无 `IN` / 范围 / `LIKE` / `OR`。
3. 表名列名加双引号转义、**大小写敏感**；`partition` 与 `select` 必须非空。
4. 固定 `ORDER BY "date" DESC` → **每张表必须有 `date` 列**。
5. 表不存在返回 `[]`；表存在性判断有 `lru_cache(512)`，运行期建表不会立即可见。
6. `select` 必须含分区/过滤/取值全部所需列；返回 `[dict]`，numeric 列为 `Decimal`。
7. `api.latest` **缺表不保护**，直接抛 SQL 异常（与 `api.query` 不同）。

本地 `standards.json` 结构：`{"standards": [{manufacturer, pc_name, user_id, model, sn, date}, ...]}`（Web 表单字段名为 `cal_date`）。

## 附录 D · 服务端行为（解释线上现象用）

| 主题 | 行为 |
|---|---|
| **权限** | 规则/脚本/模板/标准器端点用 `require_manager`（manager + admin），不是 admin 专属 |
| **脚本安全** | 受信任代码，非沙箱：普通 globals + 完整 `__builtins__`，无 import 黑名单/配额；上传时与规则加载时各 `exec` 一次模块级代码 |
| **执行约束** | `REPORT_SCRIPT_TIMEOUT_SEC`（默认 300s）daemon 线程 `join`，**超时线程不会终止**；`REPORT_JOB_TIMEOUT_SEC`（600s）看门狗；`REPORT_MAX_CONCURRENCY`（2）；插件 `Exception` 转任务 `failed` |
| **任意查询上限** | `api.sql` / `api.tables()` / `api.describe()` 走事务级 `statement_timeout`（`REPORT_SQL_TIMEOUT_MS`，默认 30000ms）；仅 `api.sql` 另有结果行数上限（`REPORT_SQL_MAX_ROWS`，默认 50000，超限报错不截断）。两者是服务端配置、运维可调；开发包台架读同名环境变量，在包内 `.env` 填同值即可对齐 |
| **只读边界** | 所有取数接口（`api.sql` / `api.query` / `api.latest` / `tables` / `describe`）共用强制只读连接 `SET default_transaction_read_only = on`，写语句由 PG 层拒绝；**这只覆盖该连接**，脚本同进程仍可另建连接 —— 「一律走 api」是纪律红线，因为只有 api 这条通道带只读、超时与日志 |
| **模板** | 对象存储 → 本地缓存，ETag 比对；上传后显式 `reset_cache()` 使规则缓存失效 |
| **打印设置** | 转 PDF 前规范化：有分节符 → 仅 `fitToPage=False`；无分节符 → 锁 A4 + `fitToWidth/fitToHeight=1` + 清 `scale` |
| **归档** | Excel/PDF 入 MinIO（键 `reports/<model>/<sn>/<filename>`），可 24h 预签名下载。**MES 上传成功后只删本地 PDF，MinIO 归档全部保留**；只有维修处置作废报告才清 MinIO 对象并标记 `purged` |
| **MES** | `POST mes_url`，`data={"sn": sn}`，`files={mes_field or type: PDF}`，超时 300s；成功 = HTTP<400 且响应 JSON `success` 为 `true`/`"true"`；`mes_void_url` 用于维修作废联动 |
| **终态** | `finalize_job` 综合渲染/PDF 状态判 `success/partial/failed`，随后无条件尝试 MES |
| **PDF mode** | `off`（默认）时 `pdf=true` 产物保持 `pending` → 任务 `partial`、MES `skipped`；需 `libreoffice` 或外部 Worker |

## 红线（一页速记）

1. **脚本 = 受信任代码**：manager/admin 可上传并执行任意 Python；模块级代码会被执行两次，**不要放 I/O、连库、起线程**。
2. **一律走 `api.sql` 取数，不要绕过 `api` 直连数据库或做网络上传**：只有 api 这条通道带只读事务、超时/行数上限与 SQL 日志；自己建连接既失去这些保护，也会让口径无法对齐。
3. **产物 `path` 必须落在 `api.work_dir` 内且文件真实存在**；`filename` 由 `path.name` 决定。
4. **模板坐标 0 基**（A1 = `(0,0)`，openpyxl 需 `+1`）；数值格式与缺数据语义照参考实现。
5. **`mes=true` 必须配 `pdf=true` 与唯一 `mes_field`**。
6. 不要假设 `api.log` 能在页面看到；排查看服务端日志与 `job.error` / `job.failed_items`。
